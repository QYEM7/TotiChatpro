# تقرير تنفيذ المرحلة الثالثة — 10 أكتوبر 2026

الموعد المطلوب: الساعة 19:00 بتوقيت بغداد. هذا تقرير تقدم موثّق، وليس إعلان جاهزية للإطلاق.

## المنجز في هذه الدفعة

- استعادة كلمة المرور عبر PKCE، وفحص وجهة رابط الاستعادة، ونموذج تعيين كلمة مرور جديدة.
- شاشة أمان الحساب: تغيير كلمة المرور، إنهاء الجلسات الأخرى، إضافة/تأكيد/إزالة عامل TOTP، وعرض الهويات المرتبطة وربط مزودي الهوية المفعّلين في الخادم.
- إزالة مستمع OAuth المكرر في Android ودعم رابط التشغيل البارد.
- حماية الطلبات من تبديل الحساب أثناء انتظار تجديد الجلسة أو تحميل البيانات.
- إرسال الهدايا من الخيارات المنقولة: خصم العملات، إضافة الماس، سجلان للمحفظة، سجل هدية، وAudit Log ضمن معاملة PostgreSQL واحدة. تحقق من عضوية الطرفين، السعر والحالة من القاعدة، ومنع الرصيد السالب والتكرار وتعارض محتوى الطلب. إذا تغير السعر المعروض، يرفض الخادم الخصم حتى يعيد المستخدم التأكيد.
- حماية هدايا CP بشرط العلاقة؛ لا تُرسل بتجاوز الربط غير المكتمل.
- شراء المتجر بالذهب/الفضة، ملكية فعلية ومدة صلاحية، وتجهيز عنصر واحد من الفئة. منع شراء المكافآت وتجهيز غير المملوك وخفض VIP النشط.
- تحويل العملات بين حسابين: أقفال محافظ بترتيب ثابت، خصم/إضافة ذريّان، مفتاح تكرار، سجل مزدوج وتدقيق. البحث عن المستلم من profiles الحقيقية.
- العمليات المالية تتحقق من الحساب المؤكد، الحظر، وجود الجلسة، وAAL2 عندما يكون TOTP مفعلاً، وتحد العمليات المالية الناجحة لكل مستخدم. تحديد معدل الطلبات المرفوضة على مستوى البوابة لم يكتمل.
- تحصين RPC الغرف: التنفيذ المميز في مخطط غير مكشوف، وواجهات Security Invoker مع تحقق الجلسة. زالت التحذيرات الأمنية التسعة السابقة.
- إصلاح سباق اتصال الصوت بعد الخروج أو تبديل الحساب، واستئناف الصوت بإيماءة المستخدم، وتفعيل echo cancellation/noise suppression/auto gain في الميكروفون.
- إدارة CRUD للجداول الستة بنماذج تعتمد على أعمدة القاعدة وخيارات تصنيف/CP من الجداول الفعلية، وتصدير CSV مع حماية صيغ الجداول. سجل تدقيق ومفاتيح تكرار للتعديل.
- صلاحيات محفوظة على الخادم: تثبيت هوية Owner عند أول دخول موثق، وإدارة منح الصلاحيات وتعيين الشريك الرئيسي بواسطة Owner فقط. Super Admin بلا منح صريحة لا يرث إدارة الكتالوجات أو الوكالات، وإدارة وكالات الشحن مخصصة لـOwner. هذه قواعد صلاحيات؛ نظام الوكالات نفسه لم يكتمل.
- إضافة .env.example بلا أسرار وتحديث CI.

## الدليل والتحقق

- اختبارات الانحدار الـ42 السابقة ناجحة، وأُضيف اختباران لعقود أمن الحساب والتحقق بخطوتين.
- اختبارات PostgreSQL على القاعدة الجديدة، داخل معاملات Rollback، دون إبقاء مستخدمين أو أرصدة اختبار:
  - `supabase/tests/phase3_gifts.sql`: التكرار، تعارض الطلب، رصيد غير كافٍ، العضوية، المستخدم المجهول، سجل المحفظة والتدقيق.
  - `supabase/tests/phase3_store.sql`: الذهب والفضة، التكرار، الملكية والتجهيز، رفض الرصيد غير الكافي.
  - `supabase/tests/phase3_transfer.sql`: حفظ مجموع العملات، التكرار، التعارض، رفض التحويل للنفس والجلسة الملغاة.
  - `supabase/tests/phase3_admin.sql`: CRUD، تثبيت Owner، منع تغيير المعرّف والجداول غير المسموحة، التكرار وحدود Super Admin والشريك الرئيسي.
  - `supabase/tests/phase3_rooms.sql`: غرفة خاصة، دعوة، انضمام، المقاعد، الكتم، الرسائل والخروج.
- فحوص المتصفح للدخول والغرف والمقاعد والدردشة والخروج، بوابة Android، الكتالوجات، ورفض الصوت عند غياب الخدمة: ناجحة. هذه اختبارات عقود بمزود اختبار، وليست إثباتاً لدخول اجتماعي أو صوت فعلي.
- فحص متصفح الإدارة: الدخول بإذن الخادم، تحميل نموذج من مخطط الجدول، إرسال تعديل واحد بمفتاح تكرار، وعرض الهاتف وتنظيف الشاشة عند الخروج؛ اختبار عقد فقط.
- اختبار REST الحقيقي للبانرات: 3 إعلانات فعلية.
- فحص Supabase الأمني: لا تحذيرات أو أخطاء؛ ملاحظتان معلوماتيتان مقصودتان لجدولي الدعوات والتدقيق الممنوعين من القراءة المباشرة.
- جميع بيانات الإنتاج الجديدة مستقلة. لا استيراد لحسابات/أرصدة/صلاحيات تجريبية من القاعدة القديمة.

تم فحص إعدادات Auth العامة فعلياً: Google وApple وFacebook غير مفعلة؛ البريد مفعّل مع وجوب التأكيد. هذا لا يثبت إعداد SMTP مخصص أو وصول الرسائل.

## ما يحتاج خدمات أو معلومات خارجية

| النظام | المطلوب |
|---|---|
| Google | Client ID/Secret وإعداد شاشة الموافقة والروابط المسموحة في Supabase Auth |
| Apple | Service ID/Team ID/Key ID/private key والمجال الموثق |
| Facebook | App ID/Secret وتفعيل التطبيق والروابط المسموحة |
| البريد | SMTP فعلي ومرسل موثق وTLS وروابط الاستعادة والتحقق |
| الصوت | LIVEKIT_URL/API_KEY/API_SECRET وخدمة TURN/STUN على مزود الصوت |
| اختبار فعلي | حسابان مؤكدان في القاعدة الجديدة وأجهزة/متصفحات تسمح بالمايك |
| الصلاحيات | هوية الشريك الرئيسي الذي يسمح له مع Owner بإدارة وكالات المضيفين |

تُضاف الأسرار إلى إعدادات Supabase أو Edge Function secrets مباشرة، ولا ترسل في المحادثة أو إلى مستودع GitHub العام.

## غير مكتمل للإطلاق

الدخول الاجتماعي والبريد وTOTP مع حساب فعلي والصوت متعدد الأجهزة لم تُثبت عملياً قبل إعداد الخدمات والحسابات. الرسائل الصوتية والتخزين، مؤثرات صوت الهدايا، CP والعلاقات، الاستبدال 30% مع تتبع مصادر الماس، خزينة Owner/الوكلاء والشحن والمكافآت، السحب والتسويات الشهرية، الوكالات وصلاحياتها، وإدارة المستخدمين والوكالات والإعدادات العامة والتقارير والمالية والتصدير Excel في لوحة الإدارة ما زالت بحاجة إلى إكمال. CRUD الكتالوجات والتصدير CSV مكتملان في هذه الدفعة. لا توجد بوابة دفع إلكتروني مضافة؛ نموذج المشروع هو Owner ثم الوكيل ثم المستخدم.

واجهات المعاينة القديمة غير المكتملة لم تتحول كلها إلى وظائف إنتاجية في هذه الدفعة. لا يصح اعتبار جميع الأزرار تعمل أو جميع معايير القبول مستوفاة.
